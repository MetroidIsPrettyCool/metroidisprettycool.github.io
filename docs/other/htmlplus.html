HTML+ Lives!

Well, actually, no it doesn't. Your browser has no goddamned idea what's going on here. Total tag soup, as far as it's concerned. But boy is it trying its hardest to make sense of it anyway! Most of it probably came through, at least.

What the Heck is HTML+?

Good question. HTML+ is a superset of the original, pre-2.0 draft HTML. It was in development for probably not more than a year, starting sometime around mid-to-late 1993 before being abandoned in early 1994.

Most of its interesting features, like tables, <TEXTAREA>, <ISINDEX>, etc. eventually got rolled into HTML 3.2 and later; but there's also a lot of stuff that never went anywhere else, like the numbered division tags <DIV1>, <DIV2>, etc. through <DIV6> (which did eventually become the unnumbered <DIV>, in a very different context), <FOOTNOTE>, <ABSTRACT>, and many more — plus attributes and possible values for attributes that also never left HTML+.

If you want better, more comprehensive resources on the subject, I recommend you take a look at the official write-up, the official review (still being hosted by W3C, perfectly preserved from 1993 and 1994!) and this great summary (from a very strange individual — I hope I don't sound like he does…) I found while researching the topic:

  • https://www.w3.org/MarkUp/HTMLPlus/htmlplus_1.html

  • https://www.w3.org/MarkUp/htmlplus_paper/htmlplus.html

  • http://www.the-pope.com/htmlplus.html

Is This Page Actually HTML+?

Sure is. If I'm reading everything right, it should be totally valid too, according to the final DTD draft.

The trouble with actually making sure about that is that I haven't been able to actually track down an SGML validating tool crusty enough to be happy with that aforementioned DTD. onsgmls and nsgmls 1.3.4 (from 1998, had to compile from source after massaging it into a modern g++ compatible form) both give the same complaints:

Is That a Good Joke?

I dunno.

It would be a better gag if any of this was actually supported by modern browsers. The Web 1.0 HTML 3.2/4.0 days are easy to parody and nostalgically revive, because <BLINK> and <MARQUEE> and big spinny GIFs are all still supported.

HTML+ was never supported. By anything. What is there to even parody? You can't be retro-cool if nobody has ever heard of or understood the relevant retro. The harder I lean into HTML+, the less you'll actually be able to see. Am I going to <LINK> a glossary to this page that you'll never be able to interact with? That's sort of stupid.

All I really can do is write a simple static page, like this one, in the intersection between valid HTML+ and tolerable HTML5. The end result of actually doing that is just a boring, web 0.0 looking text-only page with some parsing errors thrown in for flavor, again like this one. (Though I guess there's also the anachronistic stylesheet I've thrown in.)

So I guess I have to leave the question up to you: do you think HTML+ is funny? Write to your local congressperson with your response.

If It's a Superset of HTML, Does That Mean It's Not Actually HTML?

Yep. As related as C and C++, if C suddenly turned around and integrated half of the C++ standard library.

As I said earlier, your browser is doing its damnedest to understand this page as really, really malformed HTML. But it isn't! Thus, some weird behavior, and a lot of missing features from HTML+.

For example, here's a list of items that should be using gopher-style icons:

  • Item with a gopher icon

  • Item with an FTP icon

  • Item with a calculator icon

  • Item with no icon but a bunch of entities in its text: &fixed.disk; &toc; &caution; &tn3270;

but this doesn't work whatsoever, for obvious reasons. Today's <LI> doesn't even have an icon attribute!

You may also notice the weird "]>" at the top of the document, that's not supposed to be there — it's part of the SGML doctype declaration that no modern browser has any idea what to do with.

This all might make a little more sense if you open the developer console in your browser of choice and compare the raw, over the-wire-source of this file to the DOM. The HTML+ root tag <HTMLPLUS> is getting interpreted, via quirks mode, as though this were a document without a proper root tag (the browser is expecting <html>), and so it's getting inserted into a synthetic <body> in the DOM, along with the closing "]>" of the doctype declaration. Worse, my <HEAD> and <BODY> tags have also been inlined into this synthetic <BODY>; though, thanks to tolerant parsing, at least the <TITLE> is still recognized. Very funny.

Why Is It so Different?

Reading the available HTML+ literature really puts you into the headspace of where the Web was in 1993. This is a great language for publishing, not so much single page applications.

The spec reminds me a lot of Org mode actually, with its tables and enforced hierarchical divisions with headlines and inspiration from LaTeX and math markup and hyperlinked glossaries and so forth. Very, very different from the HTML we got.

It's too focused on publishing for its own good, and probably wouldn't have survived unalloyed if the web was going to grow like it did, but I have a lot of affection for it. The little standard that couldn't quite.
